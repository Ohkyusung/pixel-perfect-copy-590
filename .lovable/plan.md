
목표: 모바일에서 안정화 게이지가 올라가다 끊기는(리셋/버벅임) 현상을 줄여, 체감상 연속적으로 부드럽게 보이게 개선합니다.

1) 원인 분석 (코드 기준)
- `useStabilization.ts`에서 `setProgress`를 `requestAnimationFrame`마다 호출하고 있어, 안정화 중 매 프레임 `TouchArea` 전체가 리렌더됩니다.
- 움직임 판정이 `15px/frame` 고정 임계치 + 단발성 초과 즉시 리셋이라, 모바일 저프레임/터치 노이즈에서 가끔 오탐 리셋이 발생합니다(게이지가 “끊겨 보임”).
- `TouchArea.tsx` 상태 전환 effect가 `progress`에 의존하여 프레임마다 effect가 다시 실행됩니다.

2) 구현 계획
- 파일: `src/hooks/useStabilization.ts`
  - 움직임 판정을 “프레임 기반”에서 “시간 보정 기반”으로 변경:
    - 샘플 간 `dt`를 반영해 유효 임계치를 동적으로 보정(저FPS 오탐 감소).
  - 히스테리시스 추가:
    - 임계치 초과 1회로 즉시 리셋하지 않고, 연속 2회 이상 초과 시 리셋.
    - 단, 큰 이동은 즉시 리셋(반응성 유지).
  - 진행률 업데이트 빈도 최적화:
    - 내부 시간 계산은 유지하되 UI용 `progress` 상태 갱신은 30fps 수준으로 제한(리렌더 부담 감소).

- 파일: `src/components/TouchArea.tsx`
  - 상태 전환 effect에서 `progress` 의존 제거(또는 최소화)해서 프레임 단위 effect 재실행 방지.
  - `getFingerState(index)` 중복 호출 제거(맵 렌더 시 1회 계산)로 소폭 최적화.

- 파일: `src/components/FingerCircle.tsx`
  - 진행 링 스타일 미세 조정:
    - `stroke-dashoffset` 전환값을 프레임 업데이트와 충돌하지 않게 조정(과도한 transition 제거/축소).
    - 필요 시 `will-change` 적용으로 시각적 끊김 완화.

3) 기술 상세
- 핵심은 “오탐 리셋 감소 + 불필요 리렌더 감소”의 동시 적용입니다.
- 오탐 리셋 감소: `고정 px/frame` → `dt 보정 + 연속 초과 판정`.
- 렌더 부하 감소: `progress` 업데이트 빈도 제한 + `TouchArea`의 프레임성 effect 실행 억제.
- 결과적으로 게이지가 중간에 끊겨 보이는 빈도를 낮추고, 실제 이동 시에는 즉시성도 유지합니다.

4) 검증 계획
- 모바일 실기에서 2~5손가락으로 10회 이상 반복:
  - 손가락을 거의 고정: 게이지가 끝까지 자연스럽게 상승하는지.
  - 미세 떨림/손가락 살짝 흔들림: 불필요 리셋이 줄었는지.
  - 의도적 큰 이동: 즉시 리셋되는지.
- 기존 동작 회귀 확인:
  - 2초 안정화 후 당첨, 결과 3초 자동 초기화, 손가락 전부 제거 시 1초 빠른 초기화가 유지되는지.
